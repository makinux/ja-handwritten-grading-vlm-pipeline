# プロジェクト成果総括(2026-08-04 〜 2026-08-14)

日本語手書き答案採点 VLM の訓練パイプラインを、**追加予算ゼロ**(手元の EVO-X2 128GB+NVIDIA TITAN V 12GB のみ)で、設計書の精緻化から 1 万件合成データ生成・2B モデル訓練・配備検証・評価体系の実測駆動改定まで一巡させた記録。

## 1. 設計と検証体制

- **設計書 v2.1**(`design_doc_japanese_handwritten_grading_vlm_v2.md`): Web 裏取り+敵対的パネル第 1 回(GPT-5.6×Claude Opus×3 ラウンド、`panel_records/`)で条件付き承認。主要決定: RLVR を方式選定制へ降格/教員 4 名・√r 上限方式/筆跡収集を統合プログラム 1,350 枚に一本化/LLM 判定は凍結後単回・非ゲート。
- **Phase 0 パイプライン**(`pipeline/`): label-by-construction の垂直スライス——M1 解法プログラム(実行可能ステップ列)→ M2 誤り注入+G1(実行検証・逐語化照合)/G2(差分封じ込め)ゲート → M3 文字単位座標 GT レンダラ。
- **報酬関数の敵対的テスト**: 不正出力 1,000 件が正当出力を上回る率 <1% を訓練前に確認する体制。実バグ 3 件(コメント水増し・over-correction すり抜け・global CER の偽陽性)を検出・修正し、最終形は**逆転 0/1000**。
- **text-only プローブ**: テキストのみで誤りが当てられるリーク(AUC 0.652)を検出 → 生成器修正で 0.531 まで除去。

## 2. 生成系の実 LLM 化と 1 万件データセット

- 生成 LLM = Qwen3.6-35B-A3B(Q4_K_M、llama.cpp/Vulkan、EVO-X2)。スモーク実測 → 診断 → 方式転換のループを 3 回転し、**逐語化は「合成方式」で確定**: LLM は「式に繋がる説明句」だけを出力し、式はテンプレートから機械合成(式包含が構成的に 100%)。プロンプト指示方式は実行間分散(8〜16/20)で不採用、合成方式は 20/20×2。
- **LLM 概念オペレータ**: 誤解(移項・積の符号)を LLM が提案 → AST ホワイトリストパーサで安全検証 → プログラム変異(G2 維持)。
- **10,000 件生成(7.1 時間)+レンダリング 10,000/10,000 成功**(60.8 頁/秒)。対照 30.0%・LLM 概念オペレータ 16.2%・逐語化通過 ~95%。

## 3. 価値実証: ゼロショット → SFT → 配備

### ゼロショットベースライン(`docs/phase0_baseline_report.md`)

Qwen3-VL 2B/4B/8B×n=200: 転記・TPR は現行描画で飽和(8B CER 0.003)する一方、**位置特定 IoU@0.5 と種別分類は全モデル 0.000**——本データセットの反実仮想・細粒度ラベルが埋める価値の定量的実証。実弱点は幻覚(2B は対照の 31.4% に誤りを捏造)と採点不安定(規模と非単調)。

### Phase 1' SFT(`docs/phase1_2b_sft_report.md`)

Qwen3-VL-2B QLoRA(TITAN V 単機、9,204 件・2.5 時間):

| 指標(2B・配備形態 Q8/Vulkan・リークなし) | ゼロショット | SFT 後 |
|---|---|---|
| 誤り位置 IoU@0.5 | 0.000 | **0.795** |
| 誤り種別一致(マクロ) | 0.000 | 0.647(→タキソノミ改定後 0.964 test 内) |
| 幻覚誤り率 | 31.4% | **0.0%** |
| 検出 BACC | 0.843 | **0.990** |
| 点数完全一致 | 34.5% | **93.5%** |

- **配備経路検証**: マージ → GGUF → Q8_0 → llama.cpp(Vulkan)で品質維持を確認(5.9 秒/件)。
- **配備ギャップ ablation**: 主因=**システムプロンプト不一致**(SFT は system なし訓練)を特定・解消。量子化(Q8 vs F16)は無罪、n=50 の揺れは大(公式値は n=200 のみ)。→「SFT モデルは system メッセージなしで評価・配備」をプロトコル化。

## 4. タキソノミの実測駆動改定(`panel_records/taxonomy_20260814/`、設計書付録 C)

種別 KPI 未達(0.76 < 0.85)の原因を敵対的パネル第 2 回にかけた結果、**問いそのものが作り替えられた**:

- 実測: 「概念/移項」の **95.6% が「記法/移項符号」と答案表面の文字列レベルで一致**(観測同値)。誤解の語りは 0/765(`reason` が verbalizer に渡らない実装)。積ペアは q·r<0 で 84.2% 同値+q·r>0 は「競合オペレータ不在」による偽の識別可能領域。
- 診断: タキソノミ設計の問題ではなく、**観測から識別不能な生成 provenance を予測ターゲットにしていた**こと(label-by-construction 自体は健在)。実測 0.760 はタイブレーク条件付き上限 0.759 と 3 桁一致。
- 決定(付録 C): **識別可能粒度ラベル**(サンプル毎に観測から識別可能な最も細かい GT、再生成不要の再ラベルのみ)+**過剰主張ペナルティ**(識別不能標本への下位区分断定=不正解)+**報酬三値化**+**3 層ゲート**(データ健全性/参照・n=400 測定後に閾値設定/配備・ランタイム差 ≤0.05)+深刻度の結果由来再定義+復活条件の外部依存(中学生書き手)明記。
- 実装(タスク L)と再訓練の結果: 種別 0.760 → **0.964**(test 内)。fresh 固定層化セット eval400(507 件)での新旧直接対決では**過剰主張 90% → 1%**——「判らないときに判らないと言う」挙動の獲得(`docs/eval400_first_measurement.md`)。層 1 下限(family 0.806 < 0.90)が規定どおり発動し、閾値設定は原因調査完了まで凍結。

## 5. 検証インフラ(再利用資産)

- **評価ハーネス**(`pipeline/run_zeroshot_eval.py`): C1 入力契約・座標系(pixel/relative)・system(on/off)・タキソノミ(legacy/identifiable)・後処理(coarsen)を直交フラグで切替。すべて既定は後方互換(byte 一致検証付き)。
- **eval400 固定層化セット**: fresh 生成 507 件(ファミリ層化+下位区分全数+曖昧+対照)、再ラベルマップ付き。
- **訓練系**(`train/train_qlora.py`): TITAN V(sm_70)対応 QLoRA、前後評価内蔵、ノートブック(`kaggle/`)と同一ハイパラ。
- **開発プロセス**: 実装=Codex/レビュー=Fable 5 の分業を全タスク(G〜L、約 12 回転)に適用。各タスクに実行可能な受け入れ条件+レビュー側の独立実測一致検証。
- **運用知見**(文書化済み): EVO-X2機 はホスト RAM 30GB のため追加 llama-server は同時 1 台まで/kernel 6.17 系は amdgpu-dkms 6.12 とビルド非互換(initramfs 欠落 → boot panic の根本原因、6.8 固定で恒久対策)/TITAN V機(sm_70)は conda torch 2.5.1+cu121+MKL 2023.1 固定/日本語フォントはローカルのみ=レンダリングはローカル実行 → 画像転送。

## 6. 未解決と次の柱(重要度順)

1. **sim2real(字形バンク収集の実施)**——現行成果はすべて合成描画内。実書字への転移が本丸のゲート。タキソノミ下位区分の復活も**中学生書き手の調達**(collection_plan.md、未決・所有者なし)に律速。収集計画の実行判断が最大のボトルネック。
2. **教員間一致 r の実測**(4 名×共通 100 件、外部依存)——人手参照系 KPI の前提。
3. **層 1 原因調査**: fresh 汎化ギャップ(family 0.806)の分解——追加シード訓練(分散推定)+HF 側 eval400 測定(ランタイム分解)+弱ファミリ(計算/加減 0.53)の定性分析。
4. **RAFT/DPO**: over-correction ~4% と点数の仕上げ(三値報酬を使用)。

## 総括

合成データの「ラベルの学習可能性」は in-distribution で完全に実証された(位置 0→0.80、幻覚 31%→0%、点数 35%→94%、過剰主張 90%→1%)。機械で進められる部分はほぼ回収し、評価体系は実測に耐える形へ改定済み。**次の大きな伸びしろは物理世界側(実筆跡・教員・生徒データ)にある。**
