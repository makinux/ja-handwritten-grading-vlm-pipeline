# 手書きレンダリングの T2I 化・FT 検討書(2026-08-17 改訂第2版)

改訂履歴: 初版 2026-08-17 → **同日、敵対的パネル(A=Codex/B=Opus、3ラウンド)
の統合所見を反映して全面改訂**。討論記録と統合所見は `panel_records/t2i_*.md`。
初版の主張のうちパネルが棄却したもの: 「3層防御で label/bbox/双子を保存」
「~1MP 以内・16 の倍数でリサイズ恒等」「同一 seed で双子同一」「図形は意味
レベルだから低リスク」「Kondate 購入で上位 LoRA」「30 万頁本線への diffusion
適用」「Stage C 自給ペア学習」。

決定事項(維持): 手書き風レンダリングの強化は **Qwen-Image 系(Apache-2.0)**
で行う(ユーザー確定)。商用 API(GPT Image 2 / Nano Banana)は日本語文字品質
では最高水準だが、生成物の自社 VLM 学習利用が規約上グレーであること、
hardware_plan の外部 API 不使用方針により不採用。

## 0. パネルが確定させた大前提(初版からの構造変更)

1. **Edit 変換後のデータは label-by-construction ではない**。入力グリフを条件に
   しても、文字列・局所幾何・非変更領域を保存する拘束はなく、OCR 合格は
   「OCR が同じ文字列を返した」ことしか保証しない。正確な性格づけは
   **label-by-OCR-screening** である。
   → **スキーマに `label_by_construction: bool` を追加**し、bbox 教師付き
   主系列(Stage B'+撮像層)と Edit 系列(検品済み補助系列)を隔離する。
   Edit 系列は転記・スタイル頑健化の補助か、厳格再アノテーション済み分のみ
   bbox 用途に使う。
2. **Phase 0 には採点 KPI を測る計器が存在しない**(設計書にも、パネル両者の
   初期対案にもなかった最上流欠陥)。座標ゲートと下流効用ゲートは直列で両方
   必要であり、下流端が無い限りリアリズム投資の Go/No-Go は原理的に打てない。
   → **実生徒答案 30〜50 枚の最小獲得を Phase 0 のブロッカーに格上げ**
   (協力教師 1 名経由、最小謝金)。社員による既知文書写 100 枚は「実インク
   可読性プローブ」(転記 CER 測定専用)として有効だが、実生徒の内容分布・
   行動的レイアウトを標本しないため**採点 KPI ゲートとは呼ばない**。
3. **現行 m3_render 自体が「ピクセル厳密 bbox・双子完全共有」を満たしていない**
   (コード照合で確定)。全文字 bbox は未出力、bbox はフォントメトリクス由来で
   ブラー後、`_union` は int 切り捨て、乱数の逐次消費により**変異点以降は双子の
   ジッタ列・折返しがずれる**。→ §2 のレンダラ修正は diffusion の採否と無関係に
   必要(=どの分岐でも先行する共通基盤)。

## 1. 基本方式(維持・ただし性格づけを訂正)

プロンプト直接生成は採らず、**「フォント/グリフバンクでレンダリング →
Qwen-Image-Edit で手書き風に変換」**のグリフ条件付け方式とする(直接生成より
一字の忠実性が大幅に高いという日本語圏の実証は有効: 飯塚氏
<https://zenn.dev/kota_iizuka/articles/33219ebb8aff99>、きしだ氏
<https://nowokay.hatenablog.com/entry/2026/01/05/110344>)。ただしこれは
「label-by-construction の維持」ではなく「**破綻率の最小化+検品で弾く**」
方式である(§0-1)。

使用モデル: **Qwen-Image-Edit-2511**(2025-12-23 公開、Apache-2.0。GGUF は
コミュニティ量子化。Lightning 4-step 蒸留 LoRA で高速化)。
T2I 側は Qwen-Image-2512(図形の装飾生成のみ・§6)。

## 2. 最優先: レンダラ/スキーマ修正(全分岐共通の基盤)

Stage B' にも Edit 系列にも先行して必要(パネル全会一致・最安最高効果):

- [ ] `label_by_construction` フラグと系列隔離(§0-1)
- [ ] **mask 由来 bbox 再計算**: グリフ変換(拡縮・回転・変形)後の alpha mask
      から再計算。仕様は support ベースでなく**質量ベース**
      (「bbox+既知マージンがインク質量の 99.9% 以上を含む」——ブラーの裾が
      あるため包含率 100% は原理的に不成立)
- [ ] `_union` の右端・下端を ceil 化。全文字 bbox をメタデータに出力
- [ ] **文字 ID ベース乱数**: ジッタを文字インスタンス ID から導出し、変異点
      以降の双子ずれを除去。挿入・削除で再流し込みが起きない固定セル/アンカー
- [ ] 欠字フォント fallback の provenance 記録、`writer_consistent` の実質化

概算: 12〜20 人時、GPU 0。

## 3. Stage B': ETL グリフバンク・レンダラ(主系列)

m3_render の字形バンク TODO を **ETL 実筆グリフ**で実現する(維持)。ただし:

- **ETL9G(128×127・4bit 階調)を ETL9B(64×63 二値)より優先**。300dpi 答案で
  1 字 ≈118px に対し 9B は 1.85 倍拡大で階段状輪郭になる。9G の階調は筆致
  テクスチャ(インク濃淡)を無償で供給し、diffusion の残余価値をさらに削る
- **着手前の実データ監査(必須)**: 全 607,200 レコードを走査し、
  (a) distinct writer 数と writer×字種の被覆(「200 筆者が全字種を書いた」は
  **未照合の仮定**であり事実として使わない)、(b) 予定答案の OOV 率
  (**ETL9 は数字・英字・カタカナ・数学記号を含まない**——fallback 設計が必須)、
  (c) 9B/9G の目視比較。概算 2〜4 人時・CPU のみ
- ライセンス: 規約原文(2025-03-28 改定)は目的制限なし・無料、禁止は「データ
  自体の配布」のみ。**派生物(LoRA・合成画像・クラウド処理)は未規定**。
  運用: **AIST 照会(3 点明記)を即日送付/社内開発は止めない/社外配布局面
  のみ回答待ちでゲート**
- 手続き的リアリズム(ベースラインスプライン・サイズドリフト・弾性/TPS 変形・
  インク滲み・**取り消し線/挿入/上書き/欄外はみ出し/無解答**)を diffusion より
  先に実装する。ただし「CPU だからラベル完全保存」は無条件には成立しない——
  **各変形後に mask 基準の bbox 再計算が必須**で、強変形は字形ラベル自体を
  壊し得る(変形強度の上限を仕様化)

## 4. Stage A: Edit-2511 ゼロショット変換(条件付き・少量高級品工程)

**位置づけを変更**: 「本線の前段検証」ではなく「B' が下流評価で不足した場合
にのみ着手する条件付き工程」。全 30 万頁への適用は**採択しない**。

- **スループットの構造的制約(パネルの主要発見)**: diffusers 実装は入力を
  面積 1024² へ強制リサイズする(スキップ分岐なし・32 の倍数丸め)。したがって
  **行パッチに分割しても 1 枚あたりの計算量は下がらない**。T4 実効で
  25〜40 秒/パッチ → 30 万頁×10 パッチ ≈ **3 万 GPU 時間**(Kaggle 週 30h で
  約 19 年分)。用途は評価セット・スタイル多様化サブセット等の少量に限る
- **Go/No-Go に費用条件を追加**: 実測 s/パッチからの外挿で
  総 GPU 時間 = 83.33 × f(編集対象頁率) × k(パッチ/頁) × s(秒/パッチ) ≤ 150h。
  s/パッチの実測(100 パッチ、1〜2 GPU 時間)は安価なので早期に実施してよい。
  なお ComfyUI 側の前処理経路(リサイズ挙動)は未検証——座標格子画像での
  経路検証を実測に含める
- **合格閾値(較正済み)**: 初版の「追加 CER <1%」に代えて:
  (i) 補正後の誤りスパン bbox の 95% 以上が報酬関数の実使用 IoU 閾値
  (想定 0.5)を維持(一律 IoU≥0.9 は実寸 box で許容ずれ 1.5〜2px となり
  原理的に達成不能)、
  (ii) **双子漏洩検定**: 誤りスパンをマスクした残余領域から誤り側/清書側を
  当てる識別器の AUC ≥ 0.60 で No-Go(No-Go トリガ専用。AUC≈0.5 を「漏洩なし」
  の証明には使わない)。**必ず §2 修正後のレンダラを対照とし、Edit 前
  ベースラインからの増分で測る**(現行レンダラに元から乱数 desync 由来の
  差があるため)。パッチ単位・writer/テンプレート/pair を跨いだ分割
- **検品ループの選択バイアス対策**: OCR/VLM 棄却は「判定器が読める崩れしか
  残さない」装置になりうる。採択 400/棄却 100 の人手粗監査+誤り/清書・画数・
  乱雑度層別の棄却率差の監視を必須化(false accept ≤0.1% を主張する場合は
  採択 3,000 件監査が必要——rule of three)。判定器は Qwen3-VL 単独でなく
  独立系 OCR を併用(生成器との盲点相関ヘッジ)
- 双子への適用は「同一 seed・同一 workflow」でも**同一スタイルは保証されない**
  (条件画像が異なれば denoising 軌道が変わる)。双子一致は仮定せず上記漏洩
  検定で測る

## 5. Stage C: 凍結(初版から変更)

自給ペア(入力=フォント、出力=ETL 合成)での Edit LoRA 学習は **Phase 0 から
削除**。教師が自前レンダラ P の出力である限り実答案固有情報は増えず
(得られるのは P の近似+事前分布の内挿で、後者はゼロショットが露出させる)、
「条件追従性の改善」として正当化すると成功の極限が B' 出力そのものになる
(成功指標と目的の背反)。

**復活条件**(「予算確保後」ではなく): P の外にある教師画像が確保され、かつ
500 ペア規模の小規模 LoRA がゼロショット比で「追加 CER 半減 ∧ bbox ドリフト
中位値半減」の信頼性改善を示すこと。なお TUAT Kondate は一般 50 万円でも
**敷地外持ち出し制限がありクラウド学習と衝突**する(購入は十分条件でない。
契約時に外部クラウド処理の可否を確認)。

## 6. 手描き図形

- 第一候補(維持): matplotlib xkcd 系の決定的線揺らぎ。ただし**「意味レベル
  だから低リスク」は誤り**——グラフの傾き・交点・目盛、幾何の平行・直角、
  筆算の桁位置は局所幾何そのものがラベルである。sketch の揺らぎ振幅
  (`sketch_params` の scale)は既知上界なので、**GT = 意図座標 ± scale の
  有界膨張**として扱う
- 生徒図の行動的相(比率崩れ・閉じない曲線・二度書き・傾いた定規線)は
  手続き的に生成する
- Qwen-Image-2512 での装飾生成は、図中ラベル・数値が無い装飾要素に限定

## 9. 技術メモ(誤記訂正済み)

- LoRA 学習(Stage C 復活時): musubi-tuner(`--model_version edit-2511`、
  control 画像対応・2511 は未検証扱い)または DiffSynth-Studio
  (**`--zero_cond_t`——値なしの store_true フラグ**)。fp8+block swap で
  24GB VRAM+RAM 64GB が目安(未実測。RunPod 4090 の掲載 RAM は 41GB で
  64GB 条件を満たさない点に注意)
- リサイズ: diffusers は面積 1024²・**32 の倍数**へ丸める(スキップ分岐なし)。
  恒等化は計算式の不動点となる寸法の採用でのみ成立。「~1MP 以内なら恒等」は
  誤り(**拡大**される)
- Kaggle T4 の拘束は VRAM だけでなく**ホスト RAM(約 29GB)と 12h セッション**。
  可否は 100 パッチの実測(VRAM/RAM/速度同時計測)で確定する
