## 中心的主張への反対:「収集では埋まらない、ゆえに合成が唯一のスケール路線」(§1.4)は成り立たない

- 区分:推測(設計書内の記述同士の整合性判定は事実)/確信度 **85%**

### 第1位:評価系が「10.5ヶ月後に成功/失敗を判定できない」構造になっている

**なぜ重大か。** 最悪の失敗は「動かない」ではなく「**うまくいったか分からないまま期限が来る**」である。現状の評価設計は 4 箇所で判定不能に落ちる。

**(a) 評価者のサンプルサイズが n=2。** KPI「モデル×教員 QWK ÷ 教員間 QWK ≥ 0.9」(§7)の分母は、教員2名という**1ペアからの単一推定値**である。500件によるサンプリング誤差は、分子分母の相関を考慮すると比の 95%CI ≒ ±0.075 程度に収まり、ここは致命的でない。問題は**採点者ペア選択の分散**で、教育測定では同一課題でもペアによって重み付きκが 0.4〜0.8 と振れる。分母が偶然高いペアなら比は不当に低く、低いペアなら不当に高く出る。**分母が不安定な比を合否ゲートに使うのは設計ミス**であり、しかも 2名では分母の不安定さ自体を測れない。

**(b) KPI セットが内部矛盾している。** 点数完全一致率 ≥80% と、誤り検出 BACC 0.85・位置ヒット率 0.70 は両立しない。点数は f(種別, 深刻度, 伝播) の和なので、1誤りサンプルで点数を当てるには検出×種別×深刻度が全て当たる必要がある。BACC 0.85、種別・深刻度を各 0.8 と置けば 1誤りで約 0.54、2誤りで約 0.29。対照群 30%(幻覚率5%で 0.95)を加重しても全体で**約 0.58** にしかならない。80% を出すには他 KPI が大幅に高いか、逆に**点数関数が種別・深刻度に鈍感で点数 KPI が情報を持たない**かのいずれか。どちらにせよ現状の数値セットは検算されていない。

**(c) 公平性 KPI が訓練分布の内側でしか測れない。** 「スタイル間点数一致率 ≥98%」「字形整い度と点数の相関 |ρ| ≤0.05」は、いずれもレンダラのパラメータ空間内の指標である。訓練時に同一内容×複数スタイルを見せている以上、98% は**ほぼ自明に達成される**。実運用で問題になる「実際の生徒の乱雑な字」の不利益は人手転記セットでしか測れないが、そちらには整い度の GT がなく、かつ設計書は書き手に「年代・筆記具・丁寧さを分散」としか指示しておらず、**同一内容を複数書き手に書かせる対照設計を指定していない**。結果、達成しやすく意味の薄い KPI だけが報告され、安心して終わる。これは無害ではなく**有害**な KPI である。

**(d) GPT-5.6 テキスト側判定は交絡を消していない、向きを変えただけ。** 「判定者自身の読解誤りを排除する」という論理は正しい。しかし判定者に渡すのが**検証済み転記テキスト(=正解テキスト)**である以上、学生モデルが「3」を「8」と読んで書いたコメントは、判定者からは単に文脈外れの不当なコメントに見える。**被判定者の視覚誤りがコメント品質評価に混入する**という新しい交絡が生まれている。加えて pairwise 比較の**対抗馬が明示されていない**——対抗馬が GPT-5.6 自身の生成コメントなら、§2-4 が「構造的に回避した」はずの自己選好バイアスが復活する。

**(e) G1/G2 通過率 KPI(≥90%/≥85%)はゲートを緩めるインセンティブを作る。** 通過率が高いのは、ゲートが緩いか生成が単調かのどちらかでも起きる。測るべきは通過率ではなく**ゲートの精度と再現率**(棄却分の人手検査で真に不良だった率/通過分に混入した不良率)である。

**どう直すか。**
1. 教員を**最低4名**(6ペア)に増やし、ペア間 QWK の分散を実測。KPI を比ではなく「モデル×教員 QWK が、教員間 QWK 分布の 95%CI 下限を超えるか」に変更。増分コストは §8 の「数十万円オーダー」に対し数十万円で、**制約ではなく見落とし**である。

4. LLM 判定に渡すテキストを「検証済み GT」から「**学生モデル自身の転記出力**」に変更し、コメントの妥当性をその転記に**条件付けて**評価する。転記精度は別途 CER で独立に測る。pairwise の対抗馬は教員コメントまたは前世代学生モデルに固定し、判定者系統由来の生成物を対抗馬にしない。
5. KPI 表を提出前に**内部整合シミュレーション**にかける(下記 Phase 0 パッケージ E)。

- 区分:(a)(b)(c)(e) は事実(算術と定義から導かれる)、(d) は推測/確信度 **(a) 90% / (b) 85% / (c) 90% / (d) 75% / (e) 80%**

### 第4位:「RL が SFT データの品質問題を自己修正する」は成立せず、最も高価な工程が最も弱い根拠で採用されている

**なぜ重大か。** §M4 末尾の主張——「報酬はすべてメタデータ由来で教師モデルに依存しないため、SFT データの品質問題の多くは RL 段階で自己修正されうる」——は**論理的に成立しない**。SFT データの出力ラベルも RL の報酬も、**同一のメタデータ(注入誤りの z、レンダラ座標、ルーブリック関数値)から導出されている**。メタデータが誤っていれば SFT ラベルも報酬も同じ方向に誤る。同一ソースから導かれた信号が、同一ソース由来の誤りを訂正することはできない。設計書はこの一文で RLVR の主要な正当化を行っているが、根拠として無効である。

これが重大なのは、RLVR が**本計画で最も高価かつ最も不安定な工程**だからである(第2位で述べたとおり、Phase 1 の 3ヶ月を単独で食い潰しうる)。そして**安価な代替が一切比較検討されていない**。

- **rejection sampling + SFT:** SFT チェックポイントから best-of-k をサンプリングし、報酬でフィルタして再 SFT する。同じメタデータ報酬をそのまま使え、実装は 1〜2日、1 サイクルは数日。
- **DPO/KTO:** over-correction したサンプルを負例、忠実転記を正例にするだけで over-correction 罰を実現できる。GRPO より桁で安い。

RLVR に残る固有の正当性は「CER・IoU という**連続報酬を直接最適化できる**」点だが、設計書はそう論じていない。

**報酬設計自体にも 2 つの穴がある。**

- **7項目の重みが書かれていない。** GRPO で重み付き和を最適化すると、易しい項目(形式・スキーマ適合)が先に飽和し、難しい項目(位置 IoU)が学習されない collapse が典型的に起きる。「ダッシュボードで常時監視」は検知であって対策ではない。7次元の重み探索は 1 run 2週間では**実行不能**である。
- **忠実転記と点数が学習途中で競合する。** over-correction 罰は「誤りをそのまま写せ」と要求し、点数報酬は「基準に沿って採点せよ」と要求する。GRPO は group 内の相対優位で学習するため、同一プロンプトの group に「転記は良いが採点が悪い」「採点は良いが転記が悪い」が混ざると **advantage の符号が項目間で打ち消し合い**、学習信号が薄くなる。多目的スカラー報酬と GRPO の既知の弱点だが、設計書は扱っていない。

**どう直すか。**
1. RLVR を「採用済み」から「**Phase 1 前半の比較実験で選定**」に格下げする。同一 SFT チェックポイントから (a) GRPO、(b) rejection sampling + SFT、(c) over-correction 負例による DPO を各 1〜3日で走らせ、合成 held-out の主要指標で比較する。GRPO が有意に勝った場合のみ RLVR に 3ヶ月を投じる。
2. 報酬に**カリキュラムを適用**する(形式+転記 → 誤り有無 → 位置 → 点数)。重みの同時探索を避ける。
3. 各報酬項目を**2B モデル・1日規模の単項目 run** で個別に挙動確認してから合成する。
4. RLVR の正当化を「SFT の品質問題を修正する」から「**CER/IoU の連続量を直接最適化する**」に書き換える(こちらは成立する主張である)。

- 区分:自己修正論の不成立は事実(論理的帰結)/確信度 **90%**。代替が優位という主張は推測/確信度 **55%**。重み collapse リスクは推測/確信度 **70%**。多目的 advantage 打ち消しは推測/確信度 **60%**
- 反証条件:上記 (a)(b)(c) の 3者比較を Phase 1 前半に実施し、GRPO が (b)(c) を主要指標で 5pt 以上上回れば、私の「コスト対効果が悪い」批判は崩れる。より安価な先行検証として、**Phase 0 の 1万サンプル+2B モデルで (b) rejection sampling を 1日で回し、SFT 単独からの改善幅を測る**。改善が微小なら RLVR に賭ける根拠が(消去法で)強まる。

### 第5位:ショートカット封じが低レベル画質統計に留まり、内容リーク・モダリティ無視が残る/sim2real を「測るだけで閉じられない」6ヶ月

**なぜ重大か。** 一様レンダリング原則とペア生成原則(§M2/M3)は良い設計だが、**封じているのはレンダリング痕跡という 1 経路だけ**である。監査も「線幅・ノイズ・コントラストの分布一致検定」に限定されており、以下の 2 経路を原理的に検出できない。

- **内容レベルのリーク。** 誤り注入はミュータント再実行により以降の全ステップ値を変える。つまり誤りあり/なしのペアは**文字列そのものが異なる**。誤ると計算が汚くなる(x=3 → x=-7/2 のような分数化)ため、**分数・負号・桁数の分布が誤りの有無と相関する**。モデルは「分数が出たら誤りっぽい」を学習でき、画像の空間理解を鍛えるという設計目的が空洞化する。さらに「同一レイアウト乱数」でも文字列長が変われば行の折返しが変わるので、ペアは厳密な対照になっていない。
- **モダリティ無視ショートカット。** 入力に問題文・模範解答・ルーブリックがテキストで与えられる(§M4)。誤り注入の分布が偏っていれば(例:深刻度2の計算誤りが最頻)、**画像を見ずに事前分布から点数を当てる**戦略が有効になりうる。加えて模範解答が与えられている以上、タスクは「転記して diff を取る」に縮退し、「採点を学ぶ」部分が消える可能性がある。運用時に模範解答が常に手に入る保証はない(記述式国語では特に)。設計書のアブレーション計画にこの検証項目がない。

**もう一つは構造的な問題である。** 人手転記セット 300〜500枚は Phase 1 で構築され「sim2real ギャップを常時監視」する。だが**ギャップが大きいと判明したときに閉じる手段は M5(実データ)しかなく、M5 は契約リードタイムにより Phase 3 まで来ない**(第2位参照)。つまり **Phase 1 末〜Phase 3 の約6ヶ月間、測定はできるが対策手段がゼロ**という期間が計画上存在する。しかも設計書は 300〜500枚を全て**評価専用に固定**し、レンダラ校正に使う自由度を自ら捨てている。

加えて、レンダラの表現力に明示的な欠落がある:**鉛筆の消しゴム跡(薄いグレーの残像)が §M3 の行・ページ層に含まれていない**。実答案の主要な視覚ノイズ源の一つであり、取り消し線・訂正挿入だけでは代替できない。KPI の sim2real 劣化幅(合成 CER ≤3% → 実筆跡 CER ≤10%、3倍強)の根拠も示されていない。

**どう直すか。**
1. **text-only プローブを常設監査に追加。** transcript_gt のテキストのみから誤り有無を予測する軽量分類器を訓練し、AUC を監視する。AUC > 0.7 なら内容リークあり。数時間で実装でき、以後は生成バッチごとに自動実行できる。対策として、**誤りなし側にも「汚い数値になる問題」を意図的に混ぜて数値表現分布を揃える**(誤り注入時に分数化を伴わないオペレータを優先する等)。
2. **blind baseline をアブレーションに追加。** 画像をブランク/ガウスノイズに差し替えて評価し、点数一致率がチャンスを有意に上回るならモダリティ無視リークあり。あわせて「模範解答を入力から抜いた条件」も測り、タスクが diff に縮退していないか確認する。いずれも Phase 0 の 1万サンプル+2B モデルで各 1日。
3. **人手転記セットの書き手を分割する。** 例:訓練/レンダラ校正用 10名・150枚、評価専用 15名・250枚。書き手単位で分割すれば評価の独立性は保てる。これにより「測るだけで閉じられない」構造を解消し、Phase 1 中にレンダラのパラメータを実筆跡へ校正できる。
4. **先行 50 枚を Phase 0 に前倒し**し、消しゴム跡・筆圧・にじみなど、レンダラに欠けている実筆跡の特徴をリスト化してから Phase 1 の実装に入る。
5. sim2real 劣化幅 3倍という KPI の根拠を示すか、Phase 0 の先行 50 枚での実測値に置き換える。

- 区分:内容リークの存在可能性は推測/確信度 **75%**。モダリティ無視の可能性は推測/確信度 **50%**。「測るだけで閉じられない6ヶ月」は事実(工程表からの帰結)/確信度 **85%**。消しゴム跡の欠落は事実/確信度 **95%**
- 反証条件:上記 1. の text-only プローブで **AUC < 0.6** なら内容リークの批判は崩れる(数時間)。2. の blind baseline で点数一致率がチャンス水準なら、モダリティ無視の批判は崩れる(1日)。sim2real は Phase 0 の先行 50 枚+2B モデルで劣化幅を実測し、合成 CER の 2倍以内に収まれば私の懸念は大幅に弱まる。

## 私の議論の最も弱い点

**私は「§6 の全 Phase 完了」をプロジェクトの成功基準として勝手に置いており、その前提で第2位の批判(10.5ヶ月では終わらない)を組み立てている。** これは審査員として公平でない可能性がある。設計書 §1.3 が掲げる真の目的は「モデル世代を超えて再利用できるデータ生成基盤を国内に残す」ことであり、この基準で見れば、Phase 3(実データブリッジ+国語)が丸ごと落ちても、Phase 0〜2 で **(i) 検証ゲート付き合成パイプライン、(ii) 数学領域の学生モデル、(iii) 人手転記実筆跡評価セット、(iv) 反実仮想対照ラベル付きデータ 30万件** が残る。この 4 つは他所から買えず、次の世代のモデルにそのまま再利用できる。投資としては十分に成立しうる。

したがって、**チームが「Phase 3 は計画から外し、成功基準を『再利用可能な基盤+数学モデル+評価系の完成』と再定義する」と明言すれば、私の第2位の批判は「スケジュール失敗」ではなく「成功基準の記述漏れ」に格下げされ、大幅に弱まる。** 同様に、第1位の (b)(c)(e) は KPI の書き換えで解消するので、これも「設計の欠陥」ではなく「文書の未完成」に格下げされる。

私の批判のうち、この譲歩でも消えないのは **第3位(GPT-5.6 の便益/リスク比)と第4位(RLVR 自己修正論の不成立)と第1位 (a)(教員 n=2)** の 3 点である。この 3 点は成功基準をどう定義しても残る。

## 審査結論:**条件付き承認**

差し戻すには当たらない。中核の発想——label by construction、三権分立、ペア生成原則、一様レンダリング原則、ルーブリック条件付け——は健全であり、実データでは原理的に得られない細粒度・反実仮想ラベルという、代替のない資産を狙っている。第2版で導入された人手転記セットの前倒し、G1/G2 の機械化、GPT-5.6 の隔離設計は、いずれも初版から確実な前進である。

しかし現状のまま投資すると、**「何ができたのか判定できないまま期限が来る」確率が高い**。承認の条件を以下に列挙する。

1. **Phase 0 に上記実測パッケージ A〜I を組み込み、Phase 0 を 1.5ヶ月 → 2.5ヶ月に延長する。** A〜I の結果を Phase 1 着手の Go/No-Go 材料として提出すること。
2. **Phase 3(M5+国語拡張)を計画本体から外し、契約締結を条件とするオプション工程にする。** 同時に、プロジェクトの成功基準を「Phase 0〜2 の成果物(パイプライン・数学モデル・評価系・データ)」として明文で再定義する。
3. **コスト表に人件費・GPU 調達費・法務/契約費を金額で追加し、総投資枠を明示する。** 現状の §8 は投資判断の材料にならない。
4. **教員評価を最低4名に増やし、QWK 比 KPI を「教員間 QWK 分布の 95%CI 下限との比較」に変更する。500件の層別配分表を提出する。**
5. **GPT-5.6 を一次判定者から外し、MIT ライセンスの代替(DeepSeek V4-Pro 等)を採用する。** 継続使用する場合は「判定結果を一切の設計判断・Phase ゲート・アブレーション結論に用いない」を運用規程として文書化し、法務確認の完了を Phase 1 開始の必須ゲートとする。
6. **RLVR を「採用済み」から「Phase 1 前半の 3者比較(GRPO / rejection sampling+SFT / DPO)による選定事項」に格下げする。** §M4 の「RL が SFT の品質問題を自己修正する」という記述は撤回し、連続報酬の直接最適化という成立する論拠に置き換える。
7. **人手転記セットの書き手を訓練校正用/評価専用に分割し、同一内容×複数書き手の対照ブロックを設計に明記する。** 公平性指標は合成内と実筆跡を必ず並記する。
8. **ETL 照会に 4週間の期限と、期限超過時に代替経路へ自動切替する事前判断ルールを設ける。理研 IDR の企業申請適格の確認を Phase 0 に前倒しする。**
9. **出口(誰が使い、どう回収するか)を 1ページで補記する。** 特に「実データを既に保有する採点ベンダー」に対して、細粒度ラベルと反実仮想対照がもたらす価値を具体的に述べること。§1.4 の「唯一のスケール路線」という位置づけは「唯一の細粒度・反実仮想ラベル路線」に改めるべきである。

条件 1〜3 は Phase 1 の予算執行前に、条件 4〜9 は Phase 1 開始時点までに満たすことを求める。
