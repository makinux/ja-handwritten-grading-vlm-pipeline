## 明確な反対意見

§1.4 の「合成を唯一のスケール路線とする」および「筆跡と成績を独立化すれば採点バイアスを構造的に排除できる」という中心主張に反対する。

合成データは大規模な事前訓練手段として有望だが、実答案分布を規定するのは字形だけではない。解答中の逡巡、途中修正、筆圧・速度変化、余白利用、誤り後の自己修復、学力と可読性の相関まで含む。成人が完成済み解答を書き写した300〜500枚では、この分布を再現も検証もできない。また、スタイルと点数の独立化は合成世界内の相関を消すだけで、事前学習由来のバイアス、可読性差、レンダラ固有痕跡、実世界での交絡を排除しない。したがって本方式は「唯一の路線」ではなく、**合成事前訓練＋小規模でも自然に解いた実答案による校正**として位置づけるべきである。

# 最重要欠陥トップ5

## 1位：sim2real検証セットが、対象である「実答案」を代表していない

**事実（設計書記載）**

- 字形源の中心であるETLは成人筆跡である。
- 実筆跡評価は、成人協力者による合成解答の「書き写し」300〜500枚である。
- 自然に問題を解いた実答案はM5まで利用されず、共同研究先も未確定である。
- 数字・数式記号・かな・漢字を同一スタイル埋め込みで生成できる筆跡合成器は未選定である。

**推測を含む判定**

成人の書き写しセットは、撮像・字形ギャップの一部は測れるが、実答案特有のレイアウト形成、途中訂正、迷い、誤りと筆跡の相関を測れない。特に「同一書き手パラメータから全字種を生成する」は既存グリフの組合せでは自動的に成立せず、独立した研究課題である。

**なぜ重大か**

合成held-out、合成由来の書き写し、合成ルーブリックのすべてで高得点でも、実際の生徒答案に失敗する閉じた評価系が成立する。設計の最上位目的に対する外的妥当性がない。

**どう直すか**

- 300〜500枚をすべて書き写しに使わず、同一協力者・同一問題を用いた交差設計にする。
  - 完成解答の書き写し
  - 時間制限下で自力解答
  - 訂正・筆算を許した自力解答
- 例として30名×12枚＝360枚とし、writer-disjointで評価する。
- 可能なら50〜100枚だけでも、権利処理済みの対象年齢層の自然答案を最終評価専用に確保する。
- 実答案を確保できない場合、成果主張を「成人書き写し数学答案への転移」に限定する。
- 読めない答案には同一得点を強制せず、信頼度・棄却率・人手回付率を評価する。

**確信度：95%**

**反証条件**

Phase 0〜1で、10,000件の合成データと30名×12枚の交差セットを用い、writer-disjoint評価で以下を同時に満たすこと。

1. 自力解答セットでのBACCが合成セット比−0.05以内  
2. CERの悪化が3ポイント以内  
3. 書き写しと自力解答の性能差が統計的に小さく、95%クラスタ・ブートストラップCIが上記許容幅内  
4. 合成対実筆跡の識別器がwriter-disjointでAUROC 0.65以下  

安価な代理テストは、10名×8枚＝80枚で書き写し／自力解答差だけを先行測定すること。

## 2位：solution programの実行可能性を「自然で採点可能な誤答案の正解ラベル」と取り違えている

**事実（設計書記載）**

- 計算誤りだけでなく、概念誤り、立式誤り、言語欠落まで同一のミューテーション枠組みに含めている。
- G2は「指定位置以外に変更がないこと」を要求する一方、誤り後の全ステップを再計算する。
- 点数GTは主として `f(種別, 深刻度, 伝播)` で決定する。
- 自然さの検査は抜き取り5段階評価である。

**推測を含む判定**

プログラムの再実行が保証するのは計算トレースの機械的一貫性であって、人間らしい誤答、教育的な誤り分類、採点基準への適合ではない。概念誤りや根拠欠落は、一般には実行意味論だけで真偽を決められない。

また、G2の「指定位置以外は不変」と「下流ステップを変更」はそのままでは矛盾する。必要なのは、変異点と因果的影響範囲を分けた検証である。

最大の問題は点数GTである。現実の部分点は、注入した誤りの名称ではなく、各採点項目を答案が満たしたかで決まる。同じ符号誤りでも、その後の修復、検算、最終結論、採点方針によって点数が変わる。現在のGTでは、モデルがルーブリックを適用せず「誤り種別→点数」の合成規則を学習できる。

**なぜ重大か**

ラベルが構成的に正しいのではなく、生成器の定義に対して自己整合しているだけになる。内部KPIが高くても、教師採点との不一致を検出できない循環論法になる。

**どう直すか**

- solution programを型付きDAGにし、各ノードに前提・後件・採点項目との対応を持たせる。
- `mutation_site` と `causally_affected_nodes` を別フィールドにする。
- 誤り後の自己修復、誤り相殺、最終解だけ正しいケースを明示的に生成する。
- 点数は誤りラベルではなく、答案トレースが満たしたルーブリック項目集合から計算する。
- 「概念誤り」は再実行だけで受理せず、禁止される推論規則や反例による検証を追加する。
- train/testを `pair_id` だけでなく、問題骨格、テンプレート、オペレータ、ルーブリック族単位で分離する。未知オペレータ評価も必要である。

**確信度：93%**

**反証条件**

Phase 0の10,000ミュータントから、オペレータ別に層化した400件を教員2名が独立評価し、以下を満たすこと。

1. 最初の誤り位置一致率95%以上  
2. 誤り種別macro-F1 0.85以上  
3. 「実在しそうな生徒答案」の4以上評価が80%以上  
4. 構成点数と教員点数のQWK 0.8以上、かつ±1点一致90%以上  
5. 未知オペレータ・未知問題骨格でも同水準から5ポイント以内  

安価な代理テストは、10種類のオペレータ×20件＝200件で、自然さと点数だけを先行評価すること。

## 3位：RLVRは必要性も安定性も示されておらず、報酬ハッキング対策が監視頼みである

**事実（設計書記載）**

- 主要出力には完全な教師ラベルが存在する。
- 報酬はCER、IoU、分類、点数、コメントのID一致、JSON適合などの加重合成だが、重み・正規化・制約条件が未定義である。
- コメント品質は主に誤りID・種別への言及で評価する。
- 50,000〜100,000プロンプトでGRPO系RLVRを実施する予定である。

**推測を含む判定**

完全教師付きの構造化予測では、まずSFT、マルチタスク学習、制約デコードを使う方が単純で安定する可能性が高い。RLVRを既定路線にする根拠がない。

現報酬は、次の方策を許す。

- コメントに候補IDや誤り種別を列挙して接地報酬を稼ぐ
- 容易なJSON・点数項目を優先し、長い忠実転記を手抜きする
- 大きいbboxを出してIoU期待値を稼ぐ
- コメントを定型化し、教育的妥当性を失う
- 合成生成器の癖を学び、人手答案では悪化する

「報酬内訳を監視する」は検知策であり、防止策ではない。また、RLがSFTデータ品質を自己修正できるとの主張も、報酬自体が同じ合成メタデータ由来である以上、限定的である。

**なぜ重大か**

RLVRは工程中もっともGPU負荷と実装リスクが高い一方、合成報酬だけを改善して実性能を下げる可能性がある。10.5か月計画の主要な失敗源になる。

**どう直すか**

- RLVRを必須工程から条件付き工程へ降格する。
- JSON適合は報酬ではなく制約デコードで保証する。
- 転記、検出、位置、点数、コメントを別ヘッドまたは段階出力として測定し、各項目の最低性能制約を置く。
- 報酬関数に対し、欠落、列挙、巨大bbox、重複ID、極端に短い転記などの敵対的出力テストを作る。
- コメント品質はID一致ではなく、200件程度を教員が「正確性・具体性・不必要な断定」の軸で評価する。
- generator/operator/template-held-outと実筆跡セットをRLの早期停止指標にする。

**確信度：88%**

**反証条件**

Qwen3-VL 2B/4B、訓練20,000件、評価5,000件、H100×8で3日以内の比較実験を行い、SFTに対してRLVRが以下をすべて満たすこと。

1. 自力解答実筆跡セットのBACCを3ポイント以上改善  
2. CER、幻覚誤り率、校正誤差のいずれも悪化しない  
3. 未知オペレータでも改善が維持される  
4. 1,000件の敵対的出力に対し、不正出力が正当出力より高報酬になる率1%未満  
5. 教員コメント評価を有意に改善  

合成held-outだけの改善は反証として認めない。

## 4位：評価系が「視覚採点」「教育的コメント」「公平性」を混同している

**事実（設計書記載）**

- GPT-5.6には画像を渡さず、検証済み転記と誤りメタデータを渡す。
- 人手評価は教員2名×500件程度である。
- 公平性は主に合成スタイル交換で測る。
- M5の受け入れ層は学生モデル自身の最終解・誤り予測に依存する。

**推測を含む判定**

GPT-5.6のテキスト側判定には明確な利点がある。判定者のOCR誤りを除外し、「GTが既知の場合のコメント表現・部分点説明」に限定すれば有効である。

しかし、これはエンドツーエンドのVLM評価ではない。オラクル転記と誤りメタデータを与えるため、学生が画像を読み違えた結果や、存在しない誤りに基づく説明の危険性を評価できない。したがって「GPT-5.6による外部評価」ではなく、**オラクル条件下の教育的文章評価**と明記すべきである。

公平性評価も合成世界内の不変性にすぎない。極端に読みにくい字でも同じ点数を強制すると、公平性ではなく過剰確信になる。必要なのは点数不変性に加え、可読性に応じた棄却・信頼度の公平性である。

M5の4セル層別化も選択バイアスを解消しない。セル自体を学生の疑似ラベルで決めるため、難しい誤答が「誤りなし」や「不整合」と誤分類されて落ちる。OCRクロスチェックも両モデルが読める易しい答案を選びやすい。

**なぜ重大か**

評価が高くても、画像認識に失敗したモデル、実答案の難例を捨てるモデル、読みにくい答案へ無根拠に断定するモデルを合格させ得る。

**どう直すか**

- 評価を明確に分離する。
  1. 画像→転記・位置の視覚評価  
  2. オラクル転記→採点の推論評価  
  3. 画像→コメントまでのエンドツーエンド人手評価
- 教員500件は全件を2名が重複評価し、問題・書き手・誤り種別でクラスタ化したCIを出す。
- QWK比だけでなく、絶対QWK、MAE、重大過大／過小採点率、選択的精度を報告する。教員間QWKが低い場合の比率指標は不安定である。
- 公平性は24〜30名程度の実筆跡を同一内容に交差割付し、writer random effectを推定する。
- M5では各セルの採用例・棄却例をそれぞれ無作為に人手監査し、採用確率と誤ラベル率を推定する。
- GPT評価を繰り返しモデル選択に使うなら「訓練ループ外」という説明は弱くなる。完全な最終評価としてモデル凍結後に一度だけ使うか、法務確認の範囲をモデル選択への間接利用まで広げるべきである。

**確信度：92%**

**反証条件**

200件の層化サンプルについて、教員pairwise判定と次のGPT判定を比較する。

- オラクル転記＋メタデータ
- 学生転記＋学生の誤り出力

両条件間の順位反転率が5%未満、教員とのpairwise一致率が80%以上であり、さらにGPT順位と画像込み教員評価のSpearman相関が0.8以上なら、テキスト側評価による順位歪みへの懸念は弱まる。

M5については、4セルそれぞれ採用50件・棄却50件、計400件を人手監査し、棄却側の有用ラベル率が採用側より10ポイント超高いセルが存在しないことを示す必要がある。

## 追加で修正すべき横断的欠陥

- **KPIが生成器の容易さを測っている。** G1/G2通過率は品質ではない。単純テンプレートに寄せれば上がるため、問題骨格数、演算深度、語彙、オペレータ被覆、棄却前後の分布差を併記すべきである。
- **held-outの定義が弱い。** ランダムサンプル分割ではペア、テンプレート、乱数違いが漏れる。`pair_id`、問題骨格、オペレータ族、ルーブリック族、書き手をグループ分割する必要がある。
- **30±5%の対照群比率に根拠がない。** BACCには都合がよいが、実運用事前確率とは異なる。誤り事前確率を変えた校正曲線と閾値感度を評価すべきである。
- **座標GTの粒度が不整合である。** スキーマ例はステップbboxのみだが、誤りはトークンスパンである。文字／記号単位の座標対応、複数bbox、跨行スパンを保持しなければ位置報酬が曖昧になる。
- **人手回付設計がない。** 教育採点では平均精度だけでなく、低信頼答案を安全に保留できることが重要である。校正誤差、coverage-risk曲線、重大誤採点率をKPIに追加すべきである。
- **GPT評価の規約隔離に運用上の矛盾がある。** 結果を見て設計を変えれば間接的に開発へ利用したことになる。法的結論は別として、技術設計上は「モデル凍結後の一回限りの評価」と「開発中の評価」を区別しなければならない。

## この批判の最も弱い点

最も弱いのは、sim2realギャップを重大視しすぎている可能性である。対象が「整った短い中学代数答案のスキャン」に厳しく限定され、強い事前学習済みVLMが字形の細部より数式構造を利用でき、十分なドメインランダム化が有効なら、成人書き写し300〜500枚でも実用的な順位比較には足りる可能性がある。

この批判が崩れる条件は、前述の30名×12枚の交差実験に加え、少なくとも権利処理済み自然答案100枚で、合成学習モデルがCER悪化3ポイント以内、BACC悪化5ポイント以内、重大誤採点率5%以下をwriter・問題骨格とも完全held-outで達成することである。その結果が出るなら、合成中心路線への反対は撤回できる。ただし、それでも「公平性を構造的に排除した」「日本語手書き答案一般へ汎化した」という広い主張までは支持しない。
